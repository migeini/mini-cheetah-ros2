# Mini Cheetah 四足机器人 VMC 虚拟模型控制仿真调试总结

**文档创建日期**: 2026-08-16
**核心目标**: 解决 ROS 2 + Gazebo Harmonic 环境下，Mini Cheetah 机器人 VMC 力矩控制器在仿真中“瘫软、发散侧翻、持续震荡抖动、软趴趴”等一系列经典 Sim-to-Real 底层缺陷，最终实现磐石般的稳固站立。

## 1. 瘫软无力：依赖崩溃陷阱
- **现象**: 启动 launch 后，机器狗完全瘫软在地，毫无力矩输出。
- **原因**: 系统自带的 `tf_transformations` 库未能兼容最新的 Numpy 2.0，导致控制器节点在后台启动时瞬间静默崩溃。
- **解决方案**: 摒弃第三方依赖，手写并内置了原生的四元数到欧拉角转换函数 (`euler_from_quaternion`)，彻底杜绝了环境依赖导致的崩溃。

## 2. 状态丢失：3D 里程计配置与传感器盲区
- **现象**: 机器狗受力异常，表现为不断向上顶或毫无姿态反馈。
- **原因**: 
  1. Gazebo 并没有自动发布原本假设的 `/imu` 话题。
  2. Gazebo 默认的 `OdometryPublisher` 里程计仅在 2D 平面（Z轴和角速度强制为0）工作。
- **解决方案**: 
  - 将反馈话题从 `/imu` 切换为真实的 `/odom_ground_truth`。
  - 在 URDF 中为里程计插件强制开启 3D 模式 (`<dimensions>3</dimensions>`)，确保 Z 轴高度和三轴角速度的准确反馈。

## 3. 起飞翻滚：正反馈分配灾难
- **现象**: 机器狗在获得控制力矩后，只要稍微倾斜，就会疯狂加速翻滚，甚至四脚朝天。
- **原因**: Roll (横滚) 方向的力矩分配符号写反。当机身向左倾斜时，错误的逻辑导致左腿加力，从而加剧了向左的倾斜，引发了极其致命的“正反馈发散”。
- **解决方案**: 严格按照右手定则和物理反作用力原理，重新推导并纠正了 Roll/Pitch 的推力分配逻辑（如 Roll 倾斜时负反馈补偿力）。并且补全了缺失的角速度阻尼 ($K_d \cdot w_x, w_y$)。

## 4. 落地爆杀：引入腾空保护状态机 (Flight Phase)
- **现象**: 从 0.5m 高空生成落下时，四条腿在半空中疯狂乱踢，落地瞬间导致不对称的巨大冲击，将机身掀翻。
- **原因**: 纯 VMC 算法假设足端必然接触地面。当处于半空中时，VMC 分配的上百牛顿修正力作用于空气中，零阻力导致腿部以极高速度甩动。
- **解决方案**: 引入“飞行阶段”状态机。当 $Z > 0.32m$ 时，强行切断 VMC 力矩，使用纯关节 PD 模式将四条腿锁定在抗冲击的最佳收缩姿态 (`q_nominal = [0.0, 0.8, -1.6]`)；当降落到 $0.32m$ 以下瞬间，平滑过渡接管 VMC 支撑控制。

## 5. 持续微小抽搐：离散微分噪声极限环
- **现象**: 机器狗能够站立，但原地保持高频微小的颤动和抽搐。
- **原因**: Gazebo 仿真引擎以离散时间步长运行。里程计在差分计算速度时，会产生极高频的“速度毛刺”。这些毛刺被阻尼系数 ($K_d$) 放大，转化为几十牛顿的高频脉冲力，造成自我激发的微小极限环震荡。
- **解决方案**: 
  - 将里程计发布频率拉满匹配控制循环 (250Hz)。
  - 在接收到里程计 Twist 速度时，立刻引入 **一阶指数滑动平均滤波器 (EMA Filter)** (`alpha = 0.15`)，像降噪耳机一样完美过滤了高频微分噪声。

## 6. 静差与抖动的妥协：PID 积分升维
- **现象**: 为消除弹簧过硬引发的跳动而降低 $K_p$ 后，由于 8.5kg 躯干过重，机器狗被压得“软趴趴”的，无法保持在期望的 0.28m 高度。
- **原因**: 纯 PD 控制存在静差定律（Steady-State Error）。过高的刚度会引起延迟震荡，而过低的刚度无法抵抗重力静差。
- **解决方案**: 引入了极其强悍的 **积分控制项 (Integral Term, $K_i$)**。将 $K_p$ 降至完全不跳动的安全值 (`800`)，同时加入极高的 $K_i = 1000$ 并在控制流中对高度误差进行时间积分。积分器犹如液压千斤顶，平稳、无声且不可阻挡地将机身完美推至 0.28m 的绝对零误差高度。
