# Mini Cheetah 开发与调试日志 (今日总结)

## 1. 步态控制与原地踏步实现
- **步态逻辑重构**：在 `ik_gait_controller.py` 中实现了基于占空比的 Walk/Creep 步态。通过调整 `swing_ratio`（如原地踏步时设定为 0.25），优化了三腿支撑、一腿摆动的四足稳定性。
- **原地踏步 (March in Place)**：当订阅到 `cmd_vel` 的 `linear.z = 1.0` 时，触发原地踏步模式。

## 2. Gazebo 真实里程计 (Odometry) 闭环集成
- **URDF 插件集成**：在 `mini_cheetah.urdf.xacro` 中添加了 `gz-sim-odometry-publisher-system` 插件，用于从 Gazebo 物理引擎中获取精确的 2D 真实里程计数据。
- **ROS 2 桥接配置**：更新了 `bridge_config.yaml`，将 Gazebo 的 `/model/mini_cheetah/odometry` 话题完美桥接到 ROS 2 的 `/odom_ground_truth`。
- **替代 TF 监听**：由于之前的 `TFMessage` 桥接存在历史数据过期（TF_OLD_DATA）和不稳定问题，全面重构了控制器，改为订阅 `/odom_ground_truth`，确保位置反馈的实时性和准确性。

## 3. PID 闭环稳定控制器与世界坐标旋转
- **PID 漂移补偿**：在 `ik_gait_controller.py` 中加入了 PID 控制器，用于在原地踏步时检测并消除机器人的位置漂移。
- **坐标系旋转矩阵**：为解决机身偏航角 (Yaw) 对补偿方向的干扰，实现了完整的世界坐标系到机身局部坐标系的旋转矩阵变换，确保补偿步态的方向永远基于机器人正前方。

## 4. 深度 Bug 修复：坐标系反向引发的“正反馈疯狂倒退”
- **现象**：开启 PID 补偿后，机器人不但没有稳定，反而以 40cm/s 的速度向后倒飞。
- **物理与算法解剖**：
  - 排查发现，URDF 中的 `hip_pitch` 关节绕 `+Y` 轴旋转。根据右手螺旋定则，角度增加代表**向前摆腿**。
  - 但是，在我们编写的逆运动学 (IK) 几何求解器中，假设目标坐标 $X > 0$（足端在前方）时，算出的 `hip_pitch` 角度反而**减小**了。
  - 这种映射错位导致：当我们想让机器人**向前走**时，腿部在空中的摆动方向和在底面的蹬地方向完全反向，最终推动机器人实体**向后退**。
  - 这导致 PID 控制器产生了一个巨大的**正反馈环**：机器人向前微小漂移 -> PID 计算出要向后补偿 -> 物理引擎反而执行了猛烈向前的动作 -> 误差更大，直至满载倒飞。
- **解决方案**：在生成足端轨迹 `dx` 时，对 `actual_step_x` 进行了负号反向修正，完美对齐了 URDF 的物理旋转体系与逻辑体系。
- **结果验证**：修复后重新启动 Gazebo 并实时监控 `/odom_ground_truth`。目前机器人在原地踏步时，X 轴的漂移被死死锁定，来回振荡误差不超过 **4 毫米**，实现了真正意义上的纹丝不动！
